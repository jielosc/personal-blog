我喜欢 Markdown 的一个原因，是它不会让人过早地陷入排版。打开一个文本文件，就可以开始写。

## 从最简单的结构开始

用二级标题把文章分成几个部分，再用普通段落补充细节。一个段落只说一件事，往往比复杂的排版更有效。

**加粗**适合强调关键句，*斜体*适合轻声补充。需要引用时，可以这样写：

> 清楚地表达，是检验自己是否理解的一种方式。

### 列表也可以很轻巧

1. 先写下想解决的问题。
2. 收集例子与证据。
3. 重新组织成读者能够跟上的顺序。

待办事项则可以直接写成：

- [x] 写下初稿
- [x] 补充一个具体的例子
- [ ] 过几天再重读一次

## 给代码留一个位置

代码块会自动高亮，适合记录小技巧和实践过程。

```javascript
const notes = ['观察', '思考', '记录'];

for (const note of notes) {
  console.log(`今天也要继续${note}。`);
}
```

在句子里提到文件名，可以使用行内代码，比如 `hello-world.md`。

## 用表格整理比较

| 形式 | 适合的内容 |
| --- | --- |
| 段落 | 解释一条思路 |
| 列表 | 并列的要点与步骤 |
| 引用 | 值得停下来读的话 |
| 代码块 | 可以复现的实践过程 |

## 最后，回到文字本身

格式只是一种工具。真正值得花时间的，仍然是把例子讲具体，把逻辑说清楚，把不必要的句子删掉。

写完之后，合上编辑器，过一天再读一遍。你通常会知道哪里还可以变得更好。
